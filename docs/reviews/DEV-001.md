## Repository state

The canonical base contains the merged cross-platform Employee and portability slice. DEV-001 was
implemented from that exact base on `codex/dev-001-hardening` in the required order: research and
ADRs, Server policy, durable throttling/client identity, CI scanning/runtime dependency cleanup,
safe diagnostics/audit, and Web component tests. The final clean install and repository-wide check
pass; exact evidence appears below.

The same evidence also keeps the product pre-alpha. Cua, Lume, and Coder are declaration-only;
native desktop Providers, proof-of-possession identity, capability leases, hardened browser egress,
native keyrings, continuous takeover, executable-skill scanning, registry distribution, ownership
transfer, and the optional Office plugin lifecycle are not production capabilities.

## Fix order and security contracts

1. H1: make the Server recompute policy and minimum risk before persistence; deny unknown actions
   and reject a Node's lower-risk claim.
2. H4: make login throttling atomic and durable; use direct peer identity by default and honor
   forwarding metadata only from explicitly trusted proxies.
3. M3: add pinned, read-only production dependency and secret-scanning CI checks.
4. M1, M6, M7, and L5: reuse the client-identity and structured-error/logging boundaries instead of
   creating parallel trust rules.
5. H2, H3, M2, and M5: proceed only after complete fail-closed protocol or platform designs. The
   current disclosure and disabled/development claim is safer than an unverifiable partial control.

## Residual risk and explicit deferrals

- H2: no signed, TTL-bound, single-use capability lease exists; real side-effecting Providers stay
  disabled.
- H3/M1: Node bootstrap remains a copyable bearer credential despite one-time enrollment,
  per-Node revocation, safe storage, throttling, and pseudonymous audit. PoP, rotation, mTLS, and
  native keyrings remain future protocol/platform work.
- M2: browser egress is not an enforceable SSRF boundary until redirect and DNS/connect policy is
  enforced where the browser connects.
- M5: Windows credential protection remains Development-only until native ACL/keyring evidence.
- L3/L4: application secret heuristics are intentionally incomplete, and offline breached-password
  screening needs a separately reviewed privacy/update lifecycle.
- Structured local logs do not add remote telemetry, retention, alert routing, or distributed
  tracing. Multi-Server event/queue design also remains outside DEV-001.
