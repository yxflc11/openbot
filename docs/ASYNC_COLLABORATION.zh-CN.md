# 频道异步协作

Server 最多同时执行六个独立根任务。同一频道的不同 Bot 可以并行工作；同一 Bot 在同一频道收到的根任务依次执行。PostgreSQL 在多个调度进程之间统一约束领取与总并发，不只依赖内存状态。

## Bot 如何分工

`list_channel_bots` 返回频道当前成员的真实身份与职责。`start_task` 创建同频道子任务后立即返回 Run ID，发起方可以继续独立工作。接收方使用自己的身份、技能、记忆和插件授权。`wait_for_task` 等待当前 Run 自己创建的委派结果；原来的 `delegate_task` 仍支持创建后直接等待。同一轮多个调用可以并行启动不同分工。

委派是一条以发起 Bot 身份保存和审计的频道消息；结果是以接收 Bot 身份保存的独立回复。模型不能指定虚假作者、频道或任务树来源。不能委派给自己、祖先、频道外 Bot 或使用电脑执行配置的 Bot。每棵树最多两层委派、四个后代；整棵树共享原始任务的期限和取消范围，各 Bot 的插件和记忆权限不会互相继承。

如果发起方尚未读取分工结果就生成最终草稿，Server 会等待这些任务，把已提交的结果送回下一轮模型调用，再允许发布最终回复。继续推理仍计入原来的步骤、工具、用量和时间预算。某个同事失败可以如实汇报；创建或审计失败不能冒充已成功派发。

## 执行中追加指令

Owner 登录后可通过 `POST /api/v1/runs/:runId/steer` 发送 `{ "instruction": "…" }`。每个运行中或排队中的原生任务累计最多八条非空追加指令，每条最多 4,000 字符，指令生效后不会重置累计限制。Server 先持久化到准确的任务，再确认接收；指令在下一轮模型调用时按顺序进入上下文，不能扩大工具、附件和成员权限，也不能撤销已完成的动作。

普通频道消息仍是独立任务，不会暗中修改另一个任务。追加指令不会自动传播到同级或子任务；需要调整哪位 Bot 的工作，就选择它对应的活动任务。

最终回复提交和追加指令争用同一任务行锁。如果已接收的新指令尚未进入推理，Server 丢弃旧草稿，在原总预算内继续处理。如果最终提交先完成，后来的追加请求会被明确拒绝。取消和终态任务不能继续接收指令。

## 流式输出

已安装的 AI SDK 实际读取模型服务的 SSE 增量流。`run.output` 只展示公开正文片段，不展示推理过程、工具参数流或上游原始错误。事件包含 Server 确定的 Run、Bot、频道 ID，以及单调序号、有上限的累计草稿和步骤重置标记。下一模型步骤会替换旧草稿，只有已提交的 `message.created` 才是正式答案。

登录后的 `GET /api/v1/runs/:runId/output` 可恢复当前进程的草稿快照。草稿在任务终止后清除；完成的回复从持久化消息恢复。Server 重启不宣称能恢复未完成 token。单次模型响应最多 512 KiB、每步骤可见文本最多 8,000 字符、HTTP 最多 30 秒；卡住的 SDK 等待和上游读取也可以取消。MiniMax 因部分兼容模型会把推理标签混入正文，继续使用非流式路径。

## 实际限制

每个 Run 最多八轮模型调用和十六次实际工具调用，其中公开联网最多四次。原有 Token 阈值、整棵任务树 300 秒期限、报告上限、取消校验和 Owner 启用条件继续生效。追加指令后的继续推理和自动汇总都计入同一个预算。

Server 重启时，已有恢复流程会将中断任务标为失败，已经提交的同事回复和审计仍保留。Server 不会重放结果不明的外部动作或自动重启失败任务；Owner 可以新建任务。这是活动运行期内有明确边界的异步协作，不是无限后台代理或能跨崩溃恢复的外部工作流。

## 验证依据

确定性测试使用实际安装的 AI SDK 和单独的临时 PostgreSQL，覆盖并发身份、同 Bot 串行、非阻塞分工与发起方独立工作、结果汇总、祖先撤销和取消、准确任务的持久化追加指令、完成竞争、八条上限、旧引用上下文、SSE 增量和卡住的读取取消。模拟模型证明 Server 集成行为，不代表付费模型服务可用性或 Windows 实机测试。参见[研究记录](research/async-collaboration.md)和[原生 Agent 限制](NATIVE_AGENT.zh-CN.md)。

## 频道表情回应与成员

消息可以保存 Owner 自己从六种表情中选择的回应，通过频道事件同步。界面不虚构其他参与者、人数或 Bot 情绪。设置或取消回应是幂等操作，拒绝把回应写到另一个频道的消息；重连快照覆盖与消息记录一致的最近 100 条消息。

从群组频道移除成员会保留历史消息和 Bot 档案，在同一事务中取消该成员的活动任务与后代、过期待批请求并删除成员关系。提交后的回调停止原生与 Worker 活动请求。可以显式重新添加 Bot，但已取消的任务不会复活。直接对话的成员固定不变。频道超过 1,000 个活动任务时，需先减少积压再移除，避免无上限的数据变更。

消息操作按用户补充的参考调整：笑脸、回复和更多图标位于气泡侧边，悬停或聚焦时显示。复制、任务详情收在更多菜单中；表情选择使用支持键盘的独立浮层。气泡下方只保留已经选择的回应。最终布局需要实际窗口渲染验收，不宣称未经测量的全应用像素一致。
