# 原生 Agent

[English](NATIVE_AGENT.md) · [简体中文](NATIVE_AGENT.zh-CN.md)

OpenBot 可以在 Server 中执行有界的“模型判断 → 调用工具 → 观察结果 → 继续判断”循环。
迭代复用已发布的 Vercel AI SDK；任务、频道成员权限、回复和审计仍以 PostgreSQL 为准。

## 使用

1. 打开“设置 → 模型与 API”，选择 OpenAI 或 Anthropic，输入支持工具调用的模型 ID 和 API Key，
   勾选“启用原生 Agent”，验证并保存。元数据验证通过不代表该模型一定支持生成接口或工具调用。
2. 创建电脑配置为 `none`（不使用电脑）的 Bot，将其加入频道，选中它并发送新任务，
   例如“阅读当前频道，总结还没完成的任务”。
3. 任务会从排队变为运行中，检查器显示模型步骤和工具观察结果；成功后出现 Bot 回复并完成任务，
   失败原因显示在 Run 中。
4. 任务详情会显示“由 Server 执行”和已记录的输入/输出 Token。Owner 可以停止排队或运行中的
   原生任务；失败或取消后，可明确点击“重新提交任务”创建新任务，从原指令重新开始，
   并非从模型检查点恢复。这一操作不开放 Worker 任务取消。

默认不开启推理，已有的加密模型配置同样保持关闭。开启后，新建的 `none` 任务（包括定时提交的任务）
会将任务内容和按需读取的当前频道上下文发送给所选模型，可能产生 API 费用。最近一次开启前的旧任务
不会补跑。修改设置时需重新输入密钥；关闭或替换配置会中止正在推理的任务。Server 需持续运行；
远程 Desktop 使用其连接的 Server。

需要带来源的报告时，在任务里明确给出最多三个 HTTPS 网址，并要求生成 Markdown 报告。
例如“阅读 https://example.com，生成带引用的 report.md”。任务成功后，频道和 Run 检查器会显示
可下载的文件。网页属于不可信资料；下载内容是模型编写的文本，不作为 HTML 执行。

Desktop 使用系统“保存报告”对话框，请选择新的 `.md` 文件名；已有文件不会被覆盖。
原生桌面壳继续禁止通用浏览器下载。

原生循环会读取当前 Bot 的名称、职责和描述，作为有界上下文，并记录使用的档案版本。
档案内容不会赋予工具权限，也不能覆盖执行策略。

## 工具与限制

| 边界 | 行为 |
| --- | --- |
| `read_channel_context` | 最多 12 条有界消息，只读当前任务频道，排除任务创建后的消息 |
| `read_task_status` | 最多 8 条当前频道的任务标题和状态，排除当前任务创建后的任务 |
| `read_public_page` | 按编号读取任务明确给出的最多 3 个网址；限时 15 秒，输入最多 512 KiB，提取文本最多 6,000 UTF-8 字节 |
| `write_report` | 最多准备 2 个 Markdown 文件；正文最多 24 KiB，加上 Server 来源记录后最多 32 KiB |
| 权限 | 严格参数结构；Server 从已领取 Run 绑定频道、Bot 和网址列表，复查成员关系与状态；模型不能传任意网址或文件路径 |
| 迭代 | 最多 5 轮模型调用、8 次实际工具调用，每轮最多输出 1,024 Token；已报告累计输入达到 64,000 或输出达到 5,120 Token 后不再调用下一轮 |
| 时间与输出 | 推理限时 90 秒，单次 HTTP 30 秒；模型响应最多 512 KiB，指令/工具投影最多 16 KiB，最终回复最多 8,000 字符 |
| 并发 | 每个 Server 最多 2 个原生任务，同一频道串行；数据库条件领取防止重复执行 |
| 网络 | 固定模型官方接口，加上任务明确授权的公开 HTTPS GET；来源 DNS 结果必须全部是公网地址，连接固定到已检查 IP 并校验原始 TLS 主机名；不跟随重定向、不提供代理、不自动重试；关闭 OpenAI 响应存储 |
| 生命周期 | 回复、报告元数据、完成状态和审计一起提交；发布失败时清理已准备的报告文件；重启时将中断的运行中任务标为失败，不自动重试结果不明或失败的任务 |

进度仅记录动作与结果摘要，不记录内部思维链、密钥或上游原始错误。每步模型报告的输入/输出
Token 和模型标识会持久化；缺失或非法计数保持未知。用量面板仅汇总已加载频道/工作区样本中
已知的记录，不代表全历史、费用估算或账单。中断中的请求可能产生尚未返回的上游用量。
累计 Token 门槛阻止下一轮调用，无法撤销已发出的请求；即使缺少用量，字节、时间和步骤上限
仍生效。状态更新和停机仍依赖数据库可用。

停止操作先提交取消状态与审计，再中止活动请求；迟到的结果不能覆盖已取消任务。
密钥拒绝、限流、模型不可用、配置变化、权限撤销、工具失败和执行上限都有固定的操作提示，
不自动重试。参见[执行体验调研](research/agent-execution-experience.md)。

当前工具不开放记忆检索、技能执行、Shell、本地文件/PDF、任意网址、电脑输入、对外消息或审批决定。
使用 Worker 电脑配置的任务沿用原有调度与审批路径；原生任务需要未提供的能力时，应说明限制。
Hermes/Pi/OpenClaw 委派、浏览器观察/操作工具及任意桌面控制仍需后续适配和权限、符合性验证。

## 验证证据

测试使用真实 SDK 和两个提供方适配器，以确定性 HTTP 响应验证工具结果确实进入下一轮模型请求，
覆盖范围/参数拒绝、执行上限、配置启用、取消和持久化。一次性 PostgreSQL 集成测试覆盖并发领取、
旧任务不补跑、Worker 排除、跨频道隔离、成员撤销、事务回滚、仅一条回复和重启中断处理。
界面测试覆盖明确勾选启用，以及不虚构 Node 的 Server 进度。来源测试覆盖私有/保留地址、混合 DNS、
连接 IP 固定、原始 TLS 主机名、重定向、压缩、大小与取消；报告测试覆盖事务发布、回滚、来源记录和鉴权下载。

测试不发送付费请求，不证明真实模型可用性、回答质量或实机桌面控制。
参见[调研记录](research/native-agent-loop.md)、[网页与报告调研](research/agent-research-artifacts.md)和[执行计划](EXECUTION_PLAN.zh-CN.md)。
