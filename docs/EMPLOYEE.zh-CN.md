# 可迁移数字员工模型

[English](EMPLOYEE.md) · [简体中文](EMPLOYEE.zh-CN.md)

## 产品结论

OpenBot 的 Bot 是可迁移的数字员工，不是聊天预设，也不是运行它的那台电脑。员工持久拥有
身份、职责、策略、已学技能、允许保存的记忆、工作履历和视觉配置；工作主机只提供临时的
电脑能力。

```text
Employee       持久身份、成长、技能、记忆和策略
Worker Host    可替换的 Windows、macOS、Linux、VM、容器或受管理设备
Run            员工被分配到工作主机执行的一次可审计任务
```

更换电脑不能更换员工；复制员工也不能暗中复制原用户的账号、凭证、审批和设备权限。

## 员工个人主页

点击员工后进入统一的长期个人主页：

| 页面 | 内容 |
| --- | --- |
| 概览 | 名称、职责、简介、外观、模型策略、状态、当前主机和信任边界 |
| 进化档案 | 有证据支持的能力变化时间线 |
| 技能图谱 | 技能、前置关系、来源、版本、可信度和验证状态 |
| 运行中 | 当前阶段、观察证据、下一动作、审批以及简明决策摘要 |
| 记忆 | 工作、情景、语义和流程记忆，以及保留和删除控制 |
| 工作记录 | Run、消息、产物、审批、失败、评估和审计引用 |
| 配置 | 职责、模型偏好、能力策略、主机绑定、例行任务和导出策略 |

员工主页属于核心频道产品，不依赖未来的办公室可视化插件。频道名册、消息作者和 Bot 列表中的
头像都可以进入同一个页面。

## 进化必须有证据

这个产品方向参考了
[Hermes Agent 的 learning graph](https://github.com/NousResearch/hermes-agent/blob/63279301bcbdc185c1b07b98a9312eb0c862f26d/agent/learning_graph.py)：
技能、记忆、来源、使用情况和相互关系应该可以检查，而不是藏在一个提示词里。OpenBot 采用
这一理念，但授权仍由自己的 Server 策略决定；当前实现没有复制 Hermes 源码。

进化事件只记录真实变化，例如技能被学习、验证、升级、停用或撤销，职责和策略变更，记忆被
提升为可复用流程，评估达到阈值，或人类认证/撤销某项能力。

每条事件保存操作者、时间、原因、证据、前后版本和是否经过人工批准。等级、徽章和外观只能
概括变化，不能因此获得执行权限。

## 技能图谱

每项技能都必须版本化并记录来源。未来的可执行技能包直接采用开放的
[Agent Skills](https://github.com/agentskills/agentskills) `SKILL.md` 目录格式和官方校验器，
不会再自创一套 OpenBot 专用技能格式：

```text
Skill
├── 稳定 id 和语义版本
├── 输入、输出和所需能力
├── 前置技能和关联技能
├── 来源：内置 / 安装 / 学习 / 导入
├── 证据：成功 Run、评估和人工验证
├── 状态：候选 / 已验证 / 暂停 / 撤销
└── 策略：允许主机、风险上限和审批要求
```

自动学习只能先生成 `candidate` 技能；通过确定性测试或人工审核后才能成为 `verified`。技能
可信度可以影响推荐，但路由和授权仍由 Server 的明确策略决定。

当前生命周期 API 只登记技能图谱元数据，不会安装脚本、把 `SKILL.md` 加载到运行时或授予工具。
这些动作必须等待隔离归档、许可证/来源检查、官方格式验证以及独立的本地策略授权。

## 可见的运行思考

界面展示的是可审计的**决策轨迹**，不是模型私有的原始思维链。它包括当前目标和阶段、使用的
观察证据、选择动作的简明原因、下一步、未知项、阻塞和审批要求，以及工具调用与结构化结果。

原始隐藏推理、模型内部 token、密钥和凭证不属于该功能。这样不同模型都可以提供一致且可信的
工作过程界面。

## 记忆边界

| 类型 | 示例 | 默认导出 |
| --- | --- | --- |
| 工作记忆 | 当前任务临时状态 | 永不导出 |
| 情景记忆 | 一次任务或对话摘要 | 默认排除 |
| 语义记忆 | 经确认、可长期使用的事实 | 由用户选择 |
| 流程记忆 | 可复用步骤和已学习 Routine | 满足许可且验证后可导出 |
| 密钥引用 | 凭证或密码库引用 | 永不导出 |

每条记忆都记录来源、作用域、敏感级别、保留期限和删除信息。导入内容在用户检查来源和能力请求
之前保持隔离。

## 下载、复制与传输

三个动作必须明确区分：

| 操作 | 结果 | 身份规则 |
| --- | --- | --- |
| 导出模板 | 职责、外观、策略和选定的已验证技能 | 导入时创建新员工 |
| 复制员工 | 带用户选择并脱敏经验的本地副本 | 永远生成新的员工 id |
| 转移员工 | 员工包和选定履历的所有权交接 | 新端激活前撤销来源端访问 |

员工包是带版本和签名的归档，包含 manifest、主页配置、技能、允许的记忆、外观资源、兼容要求、
许可证和校验和。默认不包含密码、Cookie、Session、Node 身份、能力租约、原始截图、私人审计和
本地文件路径。

导入必须先预览：校验签名和版本，列出技能、记忆、资源与所需能力，提示缺少的 Provider，允许
删除可选数据，再生成本地身份。导入技能在策略检查完成前一律禁用。

当前无身份模板已经实现这一安全路径：激活会重复校验，要求匹配人工预览过的包 ID 和规范摘要，
未签名来源必须由 Owner 单独接受风险，然后生成新的本地身份并写入不可变幂等收据。它还不包含
认证所有权转移或可选记忆选择。

员工包可以携带知识和配置，但绝不能携带电脑权限。接收者必须主动将员工绑定到自己的工作主机
并授予本地策略。

## 交付顺序

1. 个人主页基础：概览、配置、Run 历史和已有产物。
2. 进化档案：从 Bot、Run 和技能变化生成只追加事件。
3. 技能注册表：版本化技能和只读关系图。
4. 记忆控制：类型、来源、敏感级别、保留、搜索和删除。
5. 安全模板导入导出：不携带私人记忆和权限。
6. 可选择记忆的复制：脱敏、预览并生成新身份。
7. 认证转移：签名所有权交接、来源撤销和接收凭据。

## 当前实现状态

`feat/cross-platform-employees` 开发线已经完成：

- 可持久化的员工进化事件、版本化技能注册表、技能依赖关系和分类记忆存储；
- 受 Owner 鉴权保护的 `GET /api/v1/bots/:botId/profile` 聚合投影；
- 新员工自动创建进化事件，并为迁移前已有 Bot 安全回填起点；
- 可从 Bot 列表、频道成员和消息作者打开的响应式七视图员工主页；
- 将结构化 Run 进度展示为决策摘要，而不是模型私有思维链；
- 受 Owner 鉴权保护的导出预览，以及只含职责、外观、执行偏好和已验证技能的带校验 JSON 模板；
- 从结构上排除身份、权限、记忆和工作历史，并在发现疑似凭证、私钥或用户本地路径时阻止下载。
- 最大 2 MiB、使用严格 schema 的导入检查接口和界面，可验证校验和、技能依赖/能力一致性、
  疑似敏感文本和当前在线工作主机兼容性；
- 不能创建员工、激活技能、保存记忆、绑定主机或授予权限的只读隔离投影；
- 经过认证的激活命令会重新校验模板和当前主机兼容性，绑定预览摘要，在单个 PostgreSQL 事务中
  生成新员工身份，把全部技能以 `candidate`、置信度 `0` 导入，并写入不可变幂等收据，不授予
  主机权限；
- 受 Owner 鉴权保护的严格命令：以 `candidate` 新增 Agent Skills 兼容元数据，并明确验证、暂停
  或永久撤销，同时追加进化证据；
- 使用条件状态更新拒绝并发审核覆盖，而且永远不修改工作主机能力声明或策略授权；
- 有界 DSSE 信封 schema，以及经过测试的 Ed25519 签名和信任库验证；签名覆盖之后实际解析的
  员工包原始字节，信封里的 keyid 提示不能单独决定信任。

HTTP 导出默认仍不签名且不含记忆。实验性的 Owner 文件密钥库已支持 Ed25519 私钥加密保存、
显式公钥信任、轮换、撤销、DSSE 签名导出、验签后隔离预览和审核后激活；它还不提供全球发布者
身份、自动传播撤销、系统钥匙串/KMS 托管、注册表安装、选择性记忆复制或所有权转移。参见
[员工包签名手册](EMPLOYEE_SIGNING.zh-CN.md)。
技能生命周期目前只完成元数据审核；自动技能
提案、可执行 Agent Skills 归档、完整 diff 审核、记忆编辑和保留控制、选择性复制员工和认证
所有权转移仍未实现。本文已经先固定它们的数据与授权边界，
贡献者可以继续实现，而不会把员工知识与工作主机权限错误绑定。

## 验收标准

- 从核心界面任何 Bot 入口都能打开同一个员工主页。
- 每项技能和进化事件都能显示来源与证据。
- 运行页展示结构化进度和决策摘要，但不泄露秘密。
- 默认员工模板不含凭证、Session、租约、Node 身份和私人记忆。
- 缺少所需 Provider 时，导入员工保持安全阻塞并明确说明原因。
- 被复制的员工在接收者重新授权前不能操作任何工作主机。
- 删除员工遵循明确保留策略，不会破坏安全审计。
