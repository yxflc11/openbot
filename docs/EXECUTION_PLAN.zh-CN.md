# 目标模式执行计划

[English](EXECUTION_PLAN.md) · [简体中文](EXECUTION_PLAN.zh-CN.md)

## 目标

持续推进 OpenBot，使它成为一套受 Grok Bot 常驻体验启发的开源、自托管、跨平台数字员工
平台。Server 始终保存唯一真相，工作主机可以替换，可迁移员工永远不能把电脑权限一起带走。

本工作流按**至少 8 小时的 Codex 目标模式持续执行**设计。完成一个切片只是检查点，不是停止
条件；只有遇到必须由用户决定、缺少授权或仓库内无法安全解决的外部依赖时才暂停。

## 当前基线

开发线已经具备：

- 持久本地频道、具名 Bot、Run、审批、产物和实时更新；
- 面向 Windows、macOS、Linux、容器、VM 和受管理设备的版本化 Node 契约；
- 包含进化、技能、安全决策摘要、记忆、记录和配置的七视图员工主页；
- 严格的 `openbot.employee/v1` 模板 schema，以及受 Owner 鉴权保护的导出预览；
- 从结构上默认排除身份、权限、记忆和工作历史；
- 有大小上限、严格、只读的导入检查，可验证校验和、语义、敏感文本和当前工作主机兼容性。

当前浏览器 Provider 仍然只读。原生桌面控制、员工包激活和生产级 Node 信任不属于这一基线。

## 执行规则

1. Employee 身份、策略、审计和路由只能以 Server 为准。
2. 工作主机上报的能力只是元数据，不是权限。
3. 模板导出、本地复制和所有权转移必须是三个独立操作。
4. 员工包先经过严格 schema 和完整性验证，才能展示内容。
5. 导入预览必须只读；激活员工是之后由 Owner 明确批准的命令。
6. 导入技能初始为禁用，不能自动绑定工作主机。
7. 默认永不导出凭证、Session、Cookie、Node 身份、租约、审批、私人记忆、原始截图或本机路径。
8. 只展示结构化观察和决策摘要，不展示模型隐藏思维链。
9. 每个切片都以针对性测试、适当的全量检查、同步文档和一个小提交结束。
10. 保留所有无关的用户文件和未提交修改。

## 首个 8 小时之后

后续顺序是：签名与发布者密钥生命周期；使用新员工 ID、默认禁用技能的审核后激活；记忆保留、
删除和选择性迁移；审批后的单次能力租约；Windows、macOS、Linux 原生 Provider 一致性；本地
复制与认证所有权转移；最后才是可选办公室可视化插件。

## 共建入口

贡献者可以分别处理协议 fixture、Provider 适配、员工包验证、员工主页无障碍、多语翻译、安全
审查和文档。每个 Pull Request 都要说明支持平台、安全边界、测试证据，以及功能属于已实现、
实验性还是规划中。
