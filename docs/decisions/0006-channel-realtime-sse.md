# ADR-0006：频道实时传输采用 REST + SSE

- 状态：Accepted
- 日期：2026-09-03

## 背景

OpenBot 的频道完全由本地 Server 提供，同一频道可能同时在手机、平板和笔记本中打开。创建消息必须先持久化，其他设备随后即时看到结果；代理断开 Server 时，浏览器还需要识别半开连接并自行恢复。

M0 只需要 Server 向浏览器推送已确认的频道事件。浏览器向 Server 的命令仍是普通 HTTP 请求，暂时不需要双向套接字协议。

## 决策

1. 消息创建继续使用 REST；只有数据库事务成功后才发布实时事件。
2. `GET /api/v1/channels/:channelId/events` 使用 Server-Sent Events，只向订阅者发送所属频道的事件。
3. 订阅建立时发送 `channel.ready`，空闲时每 15 秒发送 `heartbeat`。
4. Web 在每次收到 `channel.ready` 后读取最近历史，按消息 ID 与实时事件合并，避免快照与事件之间的竞态和重复，并补齐断线期间的数据。
5. 浏览器 35 秒未收到任何帧即认为连接失效，关闭旧连接并每 2 秒重试。
6. M0 使用进程内 realtime hub；多 Server 部署前必须替换为共享事件总线。

## 原因

SSE 与 HTTP 代理兼容，浏览器原生支持事件类型与自动连接，足以承担当前单向投影。把命令留在 REST 中可以继续使用明确的状态码、输入校验和事务边界，也避免在尚无 Node 屏幕流时提前引入一套通用 WebSocket 协议。

## 后果

- 多个设备打开同一频道时，无需轮询或刷新即可看到新消息。
- Web 能展示连接状态，并在 Server 或代理异常后自动恢复。
- 进程内 hub 不支持 Server 横向扩容，也不能跨进程重放；数据库仍是唯一真相源，重连后由历史接口补齐。
- M1 的 Node 双向控制和后续屏幕传输仍可使用 WSS/WebRTC，不受本决策限制。
