# Desktop alpha.4 核心升级

[English](CORE_UPGRADE.md) · [简体中文](CORE_UPGRADE.zh-CN.md)

这次升级优先完成频道里的 Bot 分工、可实际读取的附件，以及第三方扩展接口。原有分享仍然是分享 Bot 自己或下载产出文件，不会把一次聊天变成“任务方法模板”。

## 频道里的分工和聊天

把不同职责、电脑配置为 `none` 的 Bot 加入同一个频道。选择协调 Bot，例如提出：“请研究员查资料，再请评审检查，最后给我结论。”协调 Bot 可以通过 `list_channel_bots` 查看频道中可协作的成员，再用 `delegate_task` 指定接收者和具体任务。

Server 会保存一条由发起 Bot 署名的委派消息，并建立独立子任务。接收 Bot 使用自己的名称、职责、已审核技能、已启用记忆和插件授权完成工作，以自己的身份回复。结果会交回发起 Bot，供它汇总或继续安排下一步。频道保留消息、状态和父子任务关系，点击状态可以检查任务。正文里写另一个 Bot 的名字，不能冒充它的身份。

同一频道同时执行一棵任务树，一个 Server 最多执行两棵。一棵树最多四个子任务、两层委派，禁止委派回祖先 Bot；整棵树限时 300 秒，每个任务继续遵守现有模型轮数、工具和 Token 上限。同级委派依次执行。这是有边界的同步分工，尚不是所有 Bot 无限后台讨论：加入频道不会自动导致每个 Bot 都回复每条消息，Worker 电脑配置的 Bot 也不能被当作原生任务接收方。停止父任务会取消仍在执行的后代任务，已完成的结果保留；重启后不会自动重做中断任务。

频道呈现参考 [Grok Bot 官方页面](https://x.ai/bot)和[协作文档](https://docs.x.ai/grok-bot/chat-and-collaboration)。以公开演示可观察的身份、消息和状态表达为依据；不宣称已实现 Grok Bot 的全部行为或拿到了其内部实现。

## 附件可以放什么、如何使用

通过附件按钮一次选择多个文件。文件独立保存在当前频道，正文只记录短引用，不再将整个文件塞进 8,000 字消息额度。每个任务最多八件附件，总计 20 MiB。

| 附件类型 | 单件上限 | Bot 的使用方式 |
| --- | --- | --- |
| UTF-8 文本、Markdown、CSV/TSV、JSON/JSONL、YAML、代码、配置和日志等 | 256 KiB | 用 `read_attachment` 按页读取，返回位置、下一页位置及未读提示 |
| PNG/JPEG 图片 | 5 MiB | 作为图片消息交给 OpenAI/Anthropic 适配器；所选模型本身必须支持图片 |
| PDF | 10 MiB | 作为文件消息交给 OpenAI/Anthropic 适配器；所选模型本身必须支持 PDF |

其他格式或不兼容的服务会给出错误说明。本次未加入 Office 文档提取、音视频转写、OCR、加密 PDF 处理或任意图片解码。较长文本不保证自动通读，因为每个任务仍只有八次工具调用；Bot 应说明未读部分。子任务只能继承父任务明确携带的附件引用。

文件使用随机 ID，绑定频道并校验 SHA-256。当前附件存储上限为 256 MiB、1,024 个文件，适用于一个权威 Server 进程；暂未提供附件清理和保留策略界面。批量上传部分失败时，可保留已经成功的附件。旧版内联文本草稿仍兼容。

## 插件不再只有技能

插件页增加 MCP 服务连接。开发者按照 MCP 标准提供 Streamable HTTP 服务，用户在 OpenBot 中预览其工具名称、描述和 JSON 参数结构，审阅精确版本摘要后安装；安装后默认停用、没有 Bot 授权。随后可以启用，并把指定工具授权给指定 Bot。

每项工具可以选择不授权、逐次确认，或由用户明确认定为只读后持续使用。插件自己声称“只读”不会自动获得权限。需要确认的调用会在频道显示具体 Bot、工具和参数，60 秒后过期；Server 在真正发出调用前重新检查权限与工具声明，记录有界审计，对结果不明的外部操作不会自动重试。接收委派的 Bot 仍需拥有自己的插件授权。

第一版实际接入的是返回有界文本或结构化结果的 MCP 工具。尚未支持 MCP 资源、提示词、嵌入式应用、插件市场和自动升级，也不会在页面执行插件 JavaScript、自动启动本地程序或安装 npm 包。支持公开 HTTPS 服务；本地开发地址需要操作者在 `OPENBOT_PLUGIN_LOCAL_ENDPOINTS` 中明确列出完整回环地址，Desktop 会传递启动环境中明确设置的这个变量。插件配置和令牌在本地加密，备份时应同时保留 `objects/plugins/state.json`、对应 `.key`、数据库和文件存储。

源码随附[插件开发者手册](PLUGINS.zh-CN.md)和可运行示例。你认为合适、希望纳入 OpenBot 的扩展，可以再经过协议兼容、测试、安全边界、许可证、维护情况和平台证据审查后合入。安装第三方插件不会自动把它发布为官方功能。
