# 研究：PDF.js 6.3 依赖图一致性

2026-09-12，针对 PR #50。完整来源、精确提交、候选比较和验证边界见[英文研究](pdfjs-6.3-lock-coherence.md)。

Dependabot 将直接依赖和锁文件升级到 6.3.289，却保留根目录 6.2.108 override，导致 npm ci 在执行测试前失败。采用 Mozilla 已发布的 PDF.js 6.3.289，精确提交 `1c8020a7d4e43668ac287a3ecf9a8dbea17e4c56`，Apache-2.0；同步直接依赖、全局 override，并使用项目指定的 npm 10.9.9 重建锁文件。保留 officeparser 7.8.0 和解决 npm 工作区 override 问题的根依赖锚点。

已检查上游源码、许可、密码和无效文档测试，以及开放问题。字节输入、密码、文本条目和销毁接口兼容现有适配；新版本的动作、表单和元数据 Map 变化不涉及当前调用。#21890 的印度文字形空格问题在多个旧版本及当前版本存在，应保留文本保真度限制；#21904 涉及编辑表单后保存，不是 OpenBot 的提取流程。

不复制上游源码或测试文件，不改变 Server 的附件权限、Worker 限制、瞬时密码、摘要校验或可见失败行为。验证需要干净安装、确认只有一个 PDF.js 版本、生产依赖审计、现有真实加密及 OpenAction PDF/Office/OCR 测试、全仓检查和 macOS/Windows/容器 CI。若兼容性失败，应整体回退依赖图；不能绕过检查或恢复旧的漏洞版本。CI 通过前不宣称升级验收完成，也不宣称所有 PDF 均可准确提取。
