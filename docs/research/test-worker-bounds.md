# Research: bounded test workers

- Status: Accepted
- Date: 2026-09-10
- Existing toolchain: Vitest 4.1.11, release commit 9bd8d46, MIT; no dependency change or copied source.

Reviewed the [official maxWorkers contract](https://vitest.dev/config/maxworkers.html), [release and maintained tests](https://github.com/vitest-dev/vitest/releases/tag/v4.1.11), and installed worker configuration. The default uses all available parallelism for each independent workspace. Turbo starts multiple workspaces; the new Office/OCR worker tests compete with socket liveness tests, producing a five-second disk test timeout under the full suite while focused tests pass. Use the released `--maxWorkers=4` option for Server and Web tests and run at most two workspace test jobs concurrently. Preserve test isolation and production deadlines. This is a resource bound, not a retry or timeout increase; the full suite must pass without suppressing failures.

## Native Windows ACL integration budget

CI run 34483934167 passed Server tests but the Desktop native DACL test hit Vitest's default 5-second whole-test limit. This test starts four real Windows PowerShell processes sequentially; each production invocation already has a 15-second fail-closed deadline. The [official per-test timeout contract](https://vitest.dev/config/testtimeout) in the same reviewed Vitest 4.1.11 permits a narrow integration budget. Set this one test to 65 seconds (four existing 15-second bounds plus fixture cleanup), without changing production deadlines, mocking ACLs, retries, or global test timeouts. Hosted Windows must still complete and validate every retained/inherited ACL assertion. No source copied or dependency added.

Follow-up CI 34485275629 exposed the underlying native-process boundary: the first PowerShell process reached its unchanged 15-second production deadline with no stderr, rather than the test deadline. Reviewed [Node v22.22.2 child-process documentation/source](https://github.com/nodejs/node/blob/v22.22.2/doc/api/child_process.md) and [upstream stdin API discussion #25231](https://github.com/nodejs/node/issues/25231): async execFile creates a writable stdin pipe; processes reading it require EOF. The ACL command receives all data through its bounded environment and no stdin protocol. Close its unused stdin immediately through the documented promisified result's child handle, then await the same process result. Preserve the timeout, literal-path checks, restricted environment and fail-closed result. The real Windows ACL fixture remains the required regression evidence. No dependency or source copied.

## Disposable PostgreSQL suite targeting

CI 34488540915 exposed two older invocations that appended an exact integration filename to `npm run test`, whose existing script already includes the broad `src` filter. Vitest treats positional filters as alternatives, so the disposable-database step unnecessarily ran all 41 Server test files. Match the newer isolated lanes by invoking `npm exec --workspace @openbot/server -- vitest run <exact-file>` directly. Portable jobs still run the complete Server suite. The 50-lesson cap test deliberately executes 51 sequential task/claim/completion flows against PostgreSQL; its 5-second whole-test deadline expired at 5.33 seconds on the hosted runner. Give only that database integration case 15 seconds, preserve all 50 successful history assertions and overflow rollback checks, and require a real focused PostgreSQL run. No production deadline or assertion changes, no retries or dependency changes.

## Hosted disk integration contention

CI 34490611680 passed the now-isolated database suites, but its combined check job exceeded five seconds in the real attachment persistence/restart case. The equivalent portable suites passed; the failing check also compiled dependencies alongside Server tests and recorded 37.89 seconds of aggregate imports. The four-worker per-workspace cap still allows eight test workers plus Office/OCR children. Reduce Server and Web to two workers each while retaining two Turbo task slots. The attachment restart case validates fsync-backed data/metadata, hash/byte equality and cross-channel refusal, not a five-second disk SLA; give only this real-storage case a bounded 15-second budget, preserving the 180 KB input, fsync and every integrity/authority assertion. No production limits or retries change. Earlier four-worker evidence above records the initial mitigation; two is the final selected cap.
