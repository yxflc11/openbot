# 研究：持久频道附件与模型读取

- 状态：已批准实施
- 日期：2026-09-10
- 验收：一次选择多个附件，上传到当前频道，发送短引用；Bot 分页读取文本，或把图片/PDF 作为已有 AI SDK 的模型消息内容发送。

## 研究与复用

复用 HTTP 原始二进制请求、Hono 4.13.5（06880c4a）、AI SDK 7.0.93（6359fd58）及已安装的 OpenAI/Anthropic 适配器、Node 文件与摘要接口、write-file-atomic 8.0.0。已检索 GitHub，核对固定版本源码、测试、发布标记与 PDF 问题 #11918/#15147；具体来源、许可证和选择依据见[英文研究](channel-attachments.md)。不新增依赖，不复制上游源码。

## 支持与边界

新附件持久保存，不再把整份文件挤入消息的 8,000 字符限制。兼容旧文本附件草稿。UTF-8 文本与代码文件单个最多 256 KiB；PNG/JPEG 最多 5 MiB；PDF 最多 10 MiB。每条任务最多 8 份附件、合计 20 MiB。对象存储上限 256 MiB、1,024 份文件，孤立字节也计入容量；已有文件在重启后仍可读取。

服务端控制频道归属、随机文件标识、真实字节上限与 SHA-256。文本按明确偏移量分页返回，不把部分读取描述成全文已读。模型只能读取当前任务明确引用、属于当前频道的附件。子任务只能继承父任务已授权的附件；附件内容不能增加权限、执行文件或指挥读取其他附件。

图片/PDF 通过 OpenAI 或 Anthropic 的既有模型接口传入；具体模型仍须支持。没有增加本地 PDF 解析、OCR、解密、杀毒或图片规范化。不声明任意兼容模型可读取图片/PDF。模型拒绝、格式不支持、损坏、超限或作用域变化时明确失败，不静默忽略附件。

## 验证与限制

验证持久化、格式与签名、摘要、大小、配额、频道隔离、任务授权、文本分页、多模态请求、前端多选与失败/草稿并发。真实模型推理需与模拟测试区分。当前存储适用于既有单 Server 对象存储部署；保留期清理界面与多进程共享卷配额锁另行实施。
