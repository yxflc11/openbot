# Research: retained Desktop startup and OS credentials

- Date: 2026-09-10
- Status: Accepted for implementation
- Scope: distinguish ordinary local Server startup from initial installation; preserve the established encrypted bootstrap and existing Preview profile.

The user reports a macOS `OpenBot Preview Safe Storage` Keychain prompt and a full installation wizard on every launch. Existing `profile-compatibility.ts` already selects the legacy profile when the canonical profile has no saved setup, retaining its pre-ready encryption name. `NativeServerController` already reuses `PG_VERSION` and `bootstrap.json`; the repeated install presentation is not evidence that the database is recreated. `DesktopInstallScreen` currently labels every start as installation regardless of retained data.

Reviewed the existing reuse ledger and `desktop-local-session-recovery.md`; GitHub queries and primary sources include [Electron 44.2.0 safeStorage implementation](https://github.com/electron/electron/blob/v44.2.0/shell/browser/api/electron_api_safe_storage.cc), [44.2.0 browser startup](https://github.com/electron/electron/blob/v44.2.0/shell/browser/electron_browser_main_parts.cc), [official safeStorage platform boundary](https://www.electronjs.org/docs/latest/api/safe-storage), and [code signing](https://www.electronjs.org/docs/latest/tutorial/code-signing). Electron 44.2.0 is the existing MIT dependency, not a new wrapper. Its startup fixes macOS Keychain service/account before ready; preserving that namespace remains required. Official documentation explicitly warns that an unsigned or inconsistently signed app can prompt again on each update. Windows DPAPI does not use the macOS Keychain permission model.

Reuse the existing lifecycle and encryption. Expose a non-secret retained-installation hint and initialize/resume phase through the existing main-process state. Classify inability to access encryption as `credential_unavailable`, preserve files, and let the UI explain the OS permission action rather than suggesting a reinstall. The public hint is presence only and never bypasses subsequent regular-file, ownership/ACL, schema, digest or decryption checks. No password, ciphertext or path is exposed to the renderer.

Do not change the legacy encryption namespace, create replacement bootstrap credentials over an existing database, set plaintext encryption, change Keychain ACLs through a script, or ask for the user's password. Removing repeated update prompts requires a valid stable signing identity; code cannot promise that an ad hoc signed update will retain OS trust. No upstream source is copied. Automated checks cover the retained hint, mode, missing resources and rejected encryption; final installed UI and OS authorization remain separate evidence.
